# Step 1 — Full Repository Audit, UI Layout Assessment & Implementation Priorities

**Project**: AI-Powered Blockchain-Based Secure Examination Infrastructure for Intelligent Question Paper Generation and Distribution  
**Audit Date**: 2026-10-28  
**Scope**: Read-only repository, UI/layout, functional, security, and test baseline audit across `frontend/`, `backend/`, `ai-service/`, `backend/prisma/`, and `docs/`.

## 1. Executive Summary

The Paper Distribution System has a functioning three-tier architecture (React 19 + Tailwind CSS v4 frontend, Node.js + Express + Prisma PostgreSQL backend, and Python FastAPI + Gemini + SentenceTransformers AI service) with **147 passing backend integration tests** and **40 passing AI service unit tests**. Core academic workflows—subject/unit/topic/CO management, manual question bank authoring with immutable revisions, semantic duplicate intelligence, AI question generation and accept/reject review, examination paper blueprint construction, validation, approval workflow, and encrypted PDF storage—are implemented in code and backed by PostgreSQL.

However, two major categories of defects degrade user experience and system reliability:

1. **Systemic UI Layout, Spacing, and Typography Drift Across Steps 5–10**:
   - **Undefined Typography Classes (`text-display`, `text-title`, `text-eyebrow`)**: Six major pages ([ExaminationsPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/ExaminationsPage.tsx), [PaperListPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/PaperListPage.tsx), [PaperBuilderPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/PaperBuilderPage.tsx), [PaperPreviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/PaperPreviewPage.tsx), [ApprovalQueuePage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/ApprovalQueuePage.tsx), and [SubmissionReviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/SubmissionReviewPage.tsx)) use `text-display` and `text-title` on `<h1>`/`<h3>` headings, and [`PageHeader`](file:///c:/paper-distribution-system/frontend/src/components/ui/Card.tsx#L33) uses `text-eyebrow`. None of `--text-display`, `--text-title`, or `--text-eyebrow` are defined in [index.css](file:///c:/paper-distribution-system/frontend/src/index.css#L54-L67), causing primary page titles to collapse to default body text size (`15px` / `0.9375rem`) instead of `28px` (`--text-page-title: 1.75rem`).
   - **Misaligned Page Headers & Double Margins**: [`PageHeader`](file:///c:/paper-distribution-system/frontend/src/components/ui/Card.tsx#L31) applies `mb-8` (`32px` bottom margin) and accepts an `actions` prop, but [QuestionBankPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionBankPage.tsx#L183-L203) wraps `<PageHeader>` inside a `sm:items-center` flex row alongside external action buttons, pushing the page heading `32px` above the button row. Seven later pages bypass `<PageHeader>` altogether.
   - **AppShell Sticky Offset & Duplicate Context Provider**: [App.tsx](file:///c:/paper-distribution-system/frontend/src/App.tsx#L7) and [AppShell.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/AppShell.tsx#L64) mount duplicate nested `<InstitutionProvider>` instances. [AppShell.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/AppShell.tsx#L73-L77) renders `<DevBar />` above the `sticky top-0` header while locking the sidebar to `sticky top-16 h-[calc(100vh-4rem)]`, creating vertical offset mismatches when the dev bar is visible or expanded.
   - **Cramped Filter Grids, Raw Input Controls, and Raw Palette Colors**: [QuestionBankPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionBankPage.tsx#L221) packs 6 filter controls into `xl:grid-cols-6` inside a `max-w-5xl` container (~`135px` per dropdown), truncating labels. Later pages bypass [`Button`](file:///c:/paper-distribution-system/frontend/src/components/ui/FormControls.tsx#L21), [`TextInput`](file:///c:/paper-distribution-system/frontend/src/components/ui/FormControls.tsx#L67), [`Select`](file:///c:/paper-distribution-system/frontend/src/components/ui/FormControls.tsx#L93), and [`Badge`](file:///c:/paper-distribution-system/frontend/src/components/ui/Card.tsx#L67) in favor of raw `<input>`/`<select>` elements (`36px` vs `40px` height) and raw Tailwind palette classes (`bg-rose-600`, `bg-emerald-600`, `bg-amber-100`).
   - **Stale Static Dashboard**: [OverviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/OverviewPage.tsx#L10-L96) remains a static Step 2 placeholder displaying `"Nothing to show yet"` and `<Badge>Planned</Badge>` for features that are already implemented.

2. **High-Priority Functional & Architectural Gaps**:
   - **AI Generation Timeout & Token Truncation Risk**: Backend [`AIClient`](file:///c:/paper-distribution-system/backend/src/services/aiClient.ts#L152) enforces a hard `35,000ms` (`35s`) timeout on `/internal/ai/generate-questions`, whereas Python `ai-service` ([config.py](file:///c:/paper-distribution-system/ai-service/app/core/config.py#L53-L57), [gemini.py](file:///c:/paper-distribution-system/ai-service/app/providers/gemini.py#L220)) uses `32s` per attempt across up to 3 attempts (`ai_max_retries = 2`) plus model fallbacks (`~98s+` worst-case budget), causing the Node.js proxy to abort before Python finishes retrying or falling back. Furthermore, `ai_max_output_tokens = 2048` risks mid-JSON truncation for larger question batches (`count` up to 20).
   - **Authentication & RBAC Enforcement Gaps**: Authentication is a development header simulation ([DevBar.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/DevBar.tsx), [tenantContext.ts](file:///c:/paper-distribution-system/backend/src/middleware/tenantContext.ts#L44)) that returns `401` for all requests when `NODE_ENV=production`. Backend role checks (`userRole`) are enforced only on approval decisions and PDF generation, leaving subject, question bank, and paper builder mutations open to any role.
   - **Unimplemented Planned Scope**: Source Documents (`status: 'planned'`), Users & Memberships (`status: 'planned'`), Settings (`status: 'planned'`), structured MCQ options (`options`/`correctAnswer`), and Blockchain integrity anchoring (explicitly deferred post-Review 1).

## 3. UI Audit by Page and Component

> **Verification Basis Note**: All UI findings below are **confirmed directly from source code inspection** of CSS theme tokens ([index.css](file:///c:/paper-distribution-system/frontend/src/index.css)), layout primitives ([AppShell.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/AppShell.tsx), [Header.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/Header.tsx), [SidebarNav.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/SidebarNav.tsx), [DevBar.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/DevBar.tsx)), UI components ([Card.tsx](file:///c:/paper-distribution-system/frontend/src/components/ui/Card.tsx), [FormControls.tsx](file:///c:/paper-distribution-system/frontend/src/components/ui/FormControls.tsx)), and page components (`frontend/src/pages/*.tsx`), plus rendered PDF PNG artifacts ([page_1.png](file:///c:/paper-distribution-system/backend/storage/pdf-artifacts/page_1.png)). Interactive headless-browser viewport resizing was not executed in this turn (see Section 10).

### 3.1 Root Causes of Global UI & Layout Inconsistency

1. **Undefined Typography Utility Classes (`P0`)**:
   - **Evidence**: [index.css](file:///c:/paper-distribution-system/frontend/src/index.css#L54-L67) defines `--text-page-title` (`1.75rem`), `--text-section` (`1.0625rem`), `--text-body` (`0.9375rem`), `--text-support` (`0.875rem`), `--text-label` (`0.8125rem`), and `--text-meta` (`0.75rem`). It does **not** define `--text-display`, `--text-title`, or `--text-eyebrow`.
   - **Impact**: Six pages use `text-display` for `<h1>` titles and `text-title` for section/card headings, and [`PageHeader`](file:///c:/paper-distribution-system/frontend/src/components/ui/Card.tsx#L33) uses `text-eyebrow`. Because Tailwind v4 does not generate font-size rules for undefined tokens, `<h1>` headings on Examinations, Paper Preparation, Paper Builder, Paper Preview, Approval Queue, and Submission Review render at body size (`15px`) instead of `28px`, destroying visual hierarchy across half the application.

2. **Inconsistent Page Header Patterns & Broken Action Button Alignment (`P0`)**:
   - **Evidence**: [`PageHeader`](file:///c:/paper-distribution-system/frontend/src/components/ui/Card.tsx#L25-L45) includes `mb-8` (`32px` bottom margin) and an `actions?: ReactNode` slot.
   - **Impact**:
     - [OverviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/OverviewPage.tsx#L27) and [SubjectsPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/SubjectsPage.tsx#L132) pass `actions` into `<PageHeader>` properly.
     - [QuestionBankPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionBankPage.tsx#L183-L203) omits the `actions` prop and instead wraps `<PageHeader>` inside `<div className="flex flex-col gap-4 sm:flex-row sm:items-center sm:justify-between">` next to a sibling button `<div>`. The internal `mb-8` on `<PageHeader>` pushes the title and description `32px` higher than the `"Generate with AI"` and `"New Question"` buttons.
     - [QuestionEditorPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionEditorPage.tsx#L140), [QuestionDetailPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionDetailPage.tsx#L123), and [QuestionHistoryPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionHistoryPage.tsx#L67) place a `<Link>` back-navigation element inside a `space-y-6` wrapper above `<PageHeader>`, mixing `mb-8` with `space-y-6`.
     - [QuestionGeneratorPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionGeneratorPage.tsx#L353-L370), [GeneratedBatchReviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/GeneratedBatchReviewPage.tsx#L238-L295), [ExaminationsPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/ExaminationsPage.tsx#L176-L188), [PaperListPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/PaperListPage.tsx#L113-L128), [PaperBuilderPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/PaperBuilderPage.tsx#L343-L398), [PaperPreviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/PaperPreviewPage.tsx#L159-L214), [ApprovalQueuePage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/ApprovalQueuePage.tsx#L58-L78), and [SubmissionReviewPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/SubmissionReviewPage.tsx#L196-L246) do not use `<PageHeader>` at all, each inventing a custom header block with different spacing (`mb-6`, `pb-5 border-b`, `space-y-6`).

3. **AppShell Sticky Header / Sidebar Height Mismatch & Nested Providers (`P1`)**:
   - **Evidence**: [App.tsx](file:///c:/paper-distribution-system/frontend/src/App.tsx#L7) wraps `<RouterProvider>` in `<InstitutionProvider>`, and [AppShell.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/AppShell.tsx#L64) wraps the shell in a second nested `<InstitutionProvider>`. In [AppShell.tsx](file:///c:/paper-distribution-system/frontend/src/components/layout/AppShell.tsx#L73-L79), `<DevBar />` sits in normal document flow above `<Header className="glass sticky top-0 z-30" />` (`h-16`), while `<aside>` uses `sticky top-16 h-[calc(100vh-4rem)]`.
   - **Impact**: Double `/institutions/current` API fetches on mount; when at the top of the viewport (or when `<DevBar />` is expanded), `<DevBar />` consumes `36px–110px` of vertical viewport height not subtracted from the sidebar's `h-[calc(100vh-4rem)]`, pushing the bottom of the sidebar ("System Ready" footer) below the fold.

4. **Form Control Height & Styling Fragmentation (`P1`)**:
   - **Evidence**: [`TextInput`](file:///c:/paper-distribution-system/frontend/src/components/ui/FormControls.tsx#L71) and [`Select`](file:///c:/paper-distribution-system/frontend/src/components/ui/FormControls.tsx#L97) enforce `min-h-11 sm:min-h-10` (`40px` desktop, `44px` touch) and `bg-surface`. However, [SubjectsPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/SubjectsPage.tsx#L150-L165) and [QuestionGeneratorPage.tsx](file:///c:/paper-distribution-system/frontend/src/pages/QuestionGeneratorPage.tsx#L403-L503) use raw `<input>` and `<select>` tags with `py-2` (~`36px` height) and custom focus rings (`focus:ring-accent/20`).
   - **Impact**: Controls visibly jump in height, border radius, and focus treatment when navigating between Subject Management, Question Bank, and AI Generator.

## 5. Confirmed Defects and Security Risks

### 5.1 AI Generation Timeout & Output Truncation Root-Cause Analysis (`P0`)

1. **Proxy vs. Worker Timeout Mismatch**:
   - In [backend/src/services/aiClient.ts](file:///c:/paper-distribution-system/backend/src/services/aiClient.ts#L152-L157), `generateQuestions()` calls `this.post(..., 35_000)`, enforcing a hard **35-second** `AbortController` timeout on the Node.js-to-Python HTTP call.
   - In [ai-service/app/core/config.py](file:///c:/paper-distribution-system/ai-service/app/core/config.py#L53-L57) and [ai-service/app/providers/gemini.py](file:///c:/paper-distribution-system/ai-service/app/providers/gemini.py#L220), each Gemini API attempt has an internal timeout of `ai_request_timeout_seconds + 2.0` (`32.0s`), with `ai_max_retries = 2` (up to 3 attempts per model) plus fallback across `FALLBACK_MODELS = ("gemini-2.5-flash", "gemini-2.0-flash")` ([gemini.py](file:///c:/paper-distribution-system/ai-service/app/providers/gemini.py#L41)).
   - **Consequence**: If the primary model is slow, rate-limited (`429`), or misconfigured (e.g. `gemini-3.6-flash` returning `404` after a slow handshake, or a batch of 10+ questions taking >35s including local SentenceTransformer embedding generation for every generated item in [generation_service.py](file:///c:/paper-distribution-system/ai-service/app/services/generation_service.py)), the Node.js backend aborts the request at `35.0s` and surfaces `"AI service request timed out"` to the React UI even while the Python service is still working.

2. **Output Token Budget (`ai_max_output_tokens = 2048`) Truncation Risk**:
   - [ai-service/app/core/config.py](file:///c:/paper-distribution-system/ai-service/app/core/config.py#L57) sets `ai_max_output_tokens: int = 2048`.
   - Meanwhile, [GenerationRequest](file:///c:/paper-distribution-system/ai-service/app/schemas/generation.py#L75) allows `count` up to `20` questions (`ge=1, le=20`), and each generated question includes `stem`, `answerKey`, `explanation`, `difficulty`, `bloomLevel`, `marks`, and `rationale`. For `count >= 8`, 2,048 tokens is frequently exhausted mid-JSON, causing `ProviderMalformedOutputError` (`"Gemini returned non-JSON text"`).

3. **Invalid Default Model Name in Local `ai-service/.env`**:
   - Local `ai-service/.env` was set to `GEMINI_MODEL=gemini-3.6-flash`, which returns `404 NOT_FOUND` on Google's `v1beta` API and forces every call in [gemini.py](file:///c:/paper-distribution-system/ai-service/app/providers/gemini.py#L140-L155) to fail first before falling back to `gemini-2.5-flash`. Setting `GEMINI_MODEL=gemini-2.5-flash` eliminates the wasted failed request on every generation call.

### 5.2 PDF Renderer vs. CBIT Reference (`Social_Engineering_22CIE18.pdf`) Comparison (`P1`)

Inspection of [pdfRendererService.ts](file:///c:/paper-distribution-system/backend/src/services/pdfRendererService.ts) and the rendered PNG artifacts ([page_1.png](file:///c:/paper-distribution-system/backend/storage/pdf-artifacts/page_1.png), [page_2.png](file:///c:/paper-distribution-system/backend/storage/pdf-artifacts/page_2.png)) against the uploaded CBIT reference paper (`Social_Engineering_22CIE18.pdf`) confirms:
- **Implemented & Matching**: Top-left `[ R22 ]` regulation box, `Code No: <subjectCode>`, centered `CHAITANYA BHARATHI INSTITUTE OF TECHNOLOGY (Autonomous)` header, examination/semester/programme/course metadata lines, `Time` and `Max. Marks` row, `Note` box, Course Outcomes (`CO1`–`CO5`) reference table, and `M | CO | BT` metadata columns.
- **Discrepancies / Gaps**:
  1. **Missing Top-Right `Hall Ticket No.` 10-Box Grid**: The CBIT reference has a 10-cell boxed grid at the top right of Page 1 for the student's Hall Ticket Number.
  2. **Hardcoded Part B `(a)/(b)` and `(OR)` Heuristic**: [pdfRendererService.ts](file:///c:/paper-distribution-system/backend/src/services/pdfRendererService.ts#L300-L412) checks `section.name.toUpperCase().includes("B")` and automatically groups every 2 consecutive questions into `Q.No (a)` and `(b)` and inserts `(OR)` between pairs, regardless of whether the paper builder intended independent questions or explicit `OR` pairs.
  3. **Missing Full Boxed Table Grid & PI Column**: The CBIT reference encloses questions in a full bordered table (`Q.No | Questions | Marks | CO | TL | PI`), whereas `pdfRendererService.ts` renders borderless question rows.
